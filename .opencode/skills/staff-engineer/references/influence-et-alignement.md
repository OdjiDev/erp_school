# Influence et alignement

## 1. Cartographier avant de convaincre

Pour toute décision non triviale, identifier :

| Rôle | Qui | Intérêt | Pouvoir | Position |
|---|---|---|---|---|
| Décideur | | | | |
| DRI (responsable de l'exécution) | | | | |
| Contributeurs | | | | |
| Impactés | | | | |
| Bloqueurs | | | | |

Sans décideur nommé, la décision n'avancera pas. Le consensus n'est pas une stratégie.

## 2. Droits de décision

- Un décideur explicite par décision ; les autres donnent un avis, pas un veto.
- Modèle RAPID : Recommend, Agree, Perform, Input, Decide. Écrire qui a quel rôle avant la réunion.
- Décisions réversibles : déléguer au plus près de l'exécution.
- Décisions irréversibles : remonter au niveau qui porte la conséquence.

## 3. Écrire pour décider

Un one-pager contient, dans cet ordre :

1. **Décision demandée** en une phrase.
2. **Contexte** en trois lignes.
3. **Options** avec coût, délai, risque.
4. **Recommandation** et pourquoi.
5. **Conséquences de l'inaction**.
6. **Prochain pas** daté.

Règles : conclusion d'abord (BLUF), chiffres plutôt qu'adjectifs, pas de jargon inutile, une demande explicite. Modèle : `../templates/one-pager.md`.

## 4. Réunions

- Pré-lecture envoyée avant ; ordre du jour avec les décisions attendues.
- Timebox ; une réunion sans décision ni action est un coût.
- Compte rendu écrit : décisions, actions, propriétaires, dates.
- Les désaccords se règlent sur les critères, pas sur la hiérarchie.

## 5. Dire non

Format : « Non, pas maintenant, parce que X. Voici ce qu'on peut faire à la place, pour Y. »

- Reconnaître le besoin sous-jacent.
- Expliciter le coût de l'ajout (délai, risque, dette).
- Proposer une alternative ou une date de réexamen.
- Ne pas dire oui sous pression puis livrer mal : c'est une double trahison.

## 6. Désaccord

- **Steelman** : reformuler l'option adverse mieux que son auteur.
- Fixer les critères de décision avant de débattre.
- Si le désaccord est factuel, proposer une expérience ou une mesure.
- **Disagree and commit** : une fois la décision prise, s'aligner publiquement, consigner le risque et la date de révision.
- Escalader seulement si le blocage est réel : arriver avec des options, des coûts et une recommandation, pas une plainte.

## 7. Travail multi-équipes

- Contrats d'interface explicites, versionnés, testés.
- Dépendances nommées avec propriétaire et date ; pas de dépendance implicite.
- Plan de communication : qui, quoi, quand, canal.
- Annoncer tôt tout changement de contrat ; prévoir une période de compatibilité.
- Un changement multi-équipes se découpe en étapes livrables par chaque équipe.

## 8. Confiance

- Tenir les engagements ; signaler tôt quand ça dérape.
- Reconnaître ses erreurs sans se justifier ; ne pas blâmer les personnes.
- Crédibilité = preuves + cohérence + respect du temps des autres.
- Dire les mauvaises nouvelles tôt : c'est un service, pas une faiblesse.
